# Nghia V9.8.1 – Hold Combo Parity Design

## Context

V9.8.0 recovered the Spotify detector/watchdog stack, exact embedded detector assets, evidence-gated revive, watchdog-owned sell scheduling, and preserved the validated C2/MiuMiu/focus behavior. Deeper static analysis of the Spotify Offline binary now shows that the active farm caller graph for SIMPLE maps and Pirate maps does not use `perform_dynamic_combo` as the production combat path. The active primitive is `hold_combo_action`.

The implementation target for V9.8.1 is therefore to align Nghia with the recovered Spotify `hold_combo_action` semantics across C1/C2/B1/B3 and Pirate Den, while keeping Pirate Den 1 Hit’s one-hit farm state machine intact.

Pirate Laptop is explicitly out of scope and must not be added, changed, tested, or routed as part of this work.

## Goals

V9.8.1 must:

1. Replace the current shared SIMPLE/Pirate combat primitive with a Spotify-parity helper matching the recovered signature:
   `hold_combo_action(direction, flash_key, skill_key, hold_time)`.
2. Use the recovered action order and jitter:
   - keep the movement direction held;
   - tap Teleport/Flash;
   - wait a random 15–45 ms;
   - tap Skill;
   - wait a random 125–255 ms;
   - repeat until the combo window expires.
3. Route C1, C2, B1, and B3 through this shared primitive with a 200–500 ms combo window.
4. Route Pirate Den normal FARM through the same shared primitive with a 200–500 ms combo window.
5. Route Pirate Den normal loot sweep through the same primitive with a 1.6 s combo window.
6. Keep Pirate Den 1 Hit FARM as “move to edge → wait for spawn → perform one hit → move to opposite edge”.
7. Route Pirate Den 1 Hit loot sweep through the shared primitive with a 1.5 s combo window.
8. Keep Dynamic Combo code dormant/evidence-gated and prevent it from becoming an active caller for these maps.
9. Preserve all non-combat routing, bounds, recovery, focus, watchdog, detector, MiuMiu, All Cure, launcher, update, and session-exclusion behavior from V9.8.0.

## Evidence Model

### Direct binary evidence

The following are treated as direct Spotify binary evidence for this design:

- `hold_combo_action` exists in the recovered utility module.
- Its recovered argument/varname structure is consistent with:
  `direction, flash_key, skill_key, hold_time` plus an `end_time` local.
- Its embedded description is:
  `Combo (Bấm loạn xạ): Giả lập người chơi gõ liên tục 2 phím chứ không đè`.
- The timing constants 0.015, 0.045, 0.125, and 0.255 are in the helper’s constant block.
- `run_left_and_right` is the fallback/active caller used for SIMPLE maps C1/C2/B1/B3.
- `run_left_and_right` supplies a 200–500 ms combo duration.
- Pirate Den normal and Pirate Den 1 Hit import/use `hold_combo_action` in their farm/loot modules.
- Pirate Den normal has a 1.6 s loot-sweep combo window.
- Pirate Den 1 Hit has a 1.5 s loot-sweep combo window.
- Pirate Den 1 Hit has a one-hit edge-wait farm flow distinct from the normal Pirate spam-combo farm path.

### High-confidence structural reconstruction

The exact low-level implementation of each tap is reconstructed through the existing Nghia input bridge rather than copied byte-for-byte from the Nuitka binary. The design requires the externally observable semantics above, while preserving existing key release, stop-generation, cached HWND, and input ownership protections.

### Explicitly not used as timing source

The dormant Dynamic Combo `SPAM` timings (20–50 ms action / 50–150 ms wait) must no longer be the timing source for active C1/C2/B1/B3/Pirate normal farming. The Dynamic Combo helper remains in the codebase for forensic parity work but must not be wired into these production map callers.

## Shared Combat Primitive

The V9.8.1 shared helper conceptually behaves as:

```python
hold_combo_action(direction, flash_key, skill_key, hold_time)
```

`hold_time` is always expressed in seconds at the helper boundary. Callers with recovered 200–500 ms evidence therefore pass a randomized `0.200–0.500` second value. The fixed Pirate loot-sweep callers pass `1.6` and `1.5` seconds directly.

Required behavior:

1. Hold the movement direction through the existing input ownership layer.
2. Compute an end time from `hold_time`.
3. While not stopped and before the end time:
   - if `flash_key` is not `None`, tap `flash_key`;
   - sleep for a randomized 15–45 ms;
   - tap `skill_key`;
   - sleep for a randomized 125–255 ms.
4. Teleport enablement is resolved by the caller. If Teleport is disabled or no valid Teleport key exists, the caller passes `flash_key=None`; the helper then runs Skill-only while preserving movement and the combo-window contract.
5. Stop/generation invalidation must abort cleanly and release any owned keys.
6. Exceptions must not leave direction, Teleport, or Skill keys held.

The helper must not contain map-specific coordinates, loot logic, MiuMiu logic, watchdog logic, detector scans, or Dynamic Combo dispatch.

## Map Routing

### C1 / C2 / B1 / B3

All four SIMPLE maps continue through the existing `run_left_and_right` flow. Only the combat primitive changes.

Protected behavior that remains unchanged:

- map-specific left/right bounds;
- direction reversal;
- fall/recovery logic;
- safe-place behavior;
- loot intervals and map-specific loot coordinates;
- cached game HWND behavior;
- focus/input bridge behavior;
- stop/generation semantics.

Combat behavior becomes:

```text
hold direction
→ hold_combo_action(direction, flash_key-or-None, skill_key, random 0.200–0.500 s)
→ continue existing edge/recovery logic
```

C2 must no longer call or emulate the dormant Dynamic Combo SPAM path for its production farm timing.

### Pirate Den normal

Pirate Den normal keeps its current state machine, route coordinates, position tolerance, stuck timeout, bottom-loot cadence, top-loot cadence, and recovery behavior.

Only these combat windows change to the shared helper:

- FARM: random `0.200–0.500` s;
- bottom/loot sweep: `1.6` s.

The existing normal-Pirate route remains distinct from 1 Hit. No one-hit wait logic is introduced into normal Pirate.

### Pirate Den 1 Hit

Pirate Den 1 Hit keeps its dedicated FARM state machine:

```text
move to edge
→ wait for spawn
→ one Skill hit
→ move to the opposite edge
```

The shared spam combo must not run during its normal FARM phase.

Only its loot sweep uses the shared helper, with a `1.5` s combo window.

Top-loot behavior, right-side setup near `(178, 183)`, return route near `(114, 172)`, 1.5 s stuck behavior, and 1-Hit-specific sleep/state handling remain protected.

## Failure and Fallback Behavior

- Missing Teleport key or disabled Teleport: caller passes `flash_key=None`; helper runs Skill-only without route failure.
- Missing Skill key: fail closed for combat action and surface the existing status/error path; do not send arbitrary keys.
- Stop requested during a combo: abort immediately through the existing generation/stop contract and release owned keys.
- Input exception: release owned keys and return control to the existing route/error handler.
- No new background thread is introduced.

## Protected Subsystems

V9.8.1 must not alter behavior in:

- MiuMiu seller;
- exact detector assets and detector thresholds;
- watchdog event ownership and sell scheduling;
- revive behavior;
- All Cure evidence-gated flow;
- focus/HWND handling outside the combat primitive call path;
- launcher/update mechanism;
- session exclusion from V9.8.0;
- CAPTCHA detect/pause/alert-only policy.

No `session_monitor_worker`, `check_session`, session token enforcement, KICK-driven UI disable, CAPTCHA solver, Gemini integration, or automated CAPTCHA answer logic may be introduced.

## Test Design

### Shared helper tests

Tests must prove:

- signature accepts `direction, flash_key, skill_key, hold_time`;
- `hold_time` is seconds at the helper boundary;
- Teleport tap happens before Skill tap;
- jitter ranges are exactly 15–45 ms and 125–255 ms;
- the helper repeats until `hold_time` expires;
- `flash_key=None` produces Skill-only behavior;
- stop/generation invalidation exits without stuck keys;
- exceptions release any keys owned by the helper.

### Caller tests

Tests must prove:

- C1/C2/B1/B3 active farm path calls the shared helper;
- C1/C2/B1/B3 pass a randomized 0.200–0.500 s combo window;
- Pirate Den normal FARM passes a randomized 0.200–0.500 s combo window;
- Pirate Den normal loot sweep passes 1.6 s;
- Pirate Den 1 Hit loot sweep passes 1.5 s;
- Pirate Den 1 Hit FARM does not call the shared spam helper;
- Pirate Laptop is absent from the new routing/tests.

### Protection tests

Tests/guards must prove:

- Dynamic Combo is not an active caller for C1/C2/B1/B3 or either Pirate farm route;
- existing C2 bounds/focus/HWND/recovery behavior is unchanged;
- Pirate normal/1-Hit route constants remain unchanged except where the shared helper is called;
- MiuMiu, watchdog, detector, All Cure, launcher, update, and session-exclusion behavior remain unchanged.

### Regression and Windows preflight

Before release:

1. run all V9.7 tests;
2. run all V9.8 tests;
3. run new V9.8.1 tests;
4. run `compileall` over the final app payload;
5. run protected static guards;
6. run the real Windows default-launch smoke;
7. package Portable and Update artifacts;
8. verify both artifact hashes and required payload files;
9. upload a private V9.8.1 preflight artifact;
10. do not create the public release until that preflight passes.

## Release Strategy

This work is released as V9.8.1, not by mutating the already-published V9.8.0 assets.

The release flow mirrors the proven V9.8.0 process:

- build from the exact public V9.8.0 stable base;
- hash-gate the base before applying V9.8.1 changes;
- run the complete regression/preflight matrix;
- create a private preflight artifact first;
- publish `v9.8.1` only after explicit user approval;
- verify public Portable and Update SHA-256 values;
- update `main/latest.json` to 9.8.1 LAST.

## Acceptance Criteria

V9.8.1 is ready for publication only when all of the following are true:

1. C1/C2/B1/B3 use the recovered shared `hold_combo_action` semantics.
2. Pirate Den normal FARM uses the same shared primitive with the randomized 0.200–0.500 s window.
3. Pirate Den normal loot sweep uses 1.6 s.
4. Pirate Den 1 Hit FARM remains one-hit and never uses the spam-combo helper.
5. Pirate Den 1 Hit loot sweep uses 1.5 s.
6. Teleport-disabled/missing-Flash fallback is Skill-only and route-safe via `flash_key=None`.
7. Dynamic Combo remains dormant/evidence-gated for these callers.
8. Pirate Laptop remains out of scope.
9. All V9.7, V9.8, and V9.8.1 tests pass.
10. Windows launcher smoke passes.
11. Protected subsystems remain unchanged.
12. Private preflight passes before any public release action.
13. Public asset hashes are verified before `latest.json` is updated.

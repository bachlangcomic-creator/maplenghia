# Nghia V10.0.1 Spotify Stability Parity Design

## Goal
Improve the stability of the existing Spotify-compatible legacy maps without adding new map features or changing Strategy V10 behavior.

## In scope
- Legacy Spotify profiles only: C1/C2/B1/B3 SIMPLE, Bunny, Stand Still/C1 Stand, Pirate2, Pirate2 1-Hit.
- Preserve the dedicated minimap-only main farm worker and cached 0.2 s focus worker architecture.
- Preserve the recovered seven-stage main-farm order: STATE/GATE -> SELL_SAFE -> PET -> RECOVERY -> BUFF1 -> BUFF2 -> PROFILE DISPATCH.
- Preserve all existing Pirate2/Pirate2-1Hit route timing/state logic unless a regression test proves a stability defect.

## Correction 1: lost-position arbitration
The recovered Spotify worker owns the 0.1 / 1.5 / 3.0 second reacquire stages. At >=3.0 s the reconstructed worker runs random_move. V10.0.0 can then immediately invoke the separate Nghia escalating recovery in the same tick, causing two recovery policies to contend.

V10.0.1 must let the recovered worker stage own the 3.0-second transition. In Spotify runtime parity mode, the generic Nghia recovery fallback must not run until SPOTIFY_RECOVERY_POSITION_HARD (4.5 s). Non-parity behavior remains unchanged.

Expected parity sequence in exact runtime mode:
- <0.1 s: grace.
- 0.1..<1.5 s: right-flash reacquire stage, once.
- 1.5..<3.0 s: left-flash reacquire stage, once.
- >=3.0 s: random_move reacquire stage, once.
- >=4.5 s only: Nghia safety fallback may escalate if position is still lost.

## Correction 2: C2 default lane policy
Adaptive Y is a Nghia extension, not Spotify evidence. Fresh V10.0.1 configurations should default C2 Adaptive Y to OFF so legacy C2 uses the fixed LEFT_Y/RIGHT_Y profile from maps.json, matching the Spotify route model.

Existing saved configs remain authoritative: if c2_adaptive_y_enabled is explicitly present in the user config, its saved value is respected. No forced migration rewrites user choice.

## Hard isolation requirements
- `nghia_strategy_v10.py` must remain byte-for-byte unchanged from V10.0.0.
- `maps.json` must remain byte-for-byte unchanged from V10.0.0.
- Map Builder and V10 Strategy profile schema/dispatch must remain unchanged.
- No new combat, TP, loot, or map modes.
- Pirate2/Pirate2-1Hit, Bunny, Stand, MiuMiu, watchdog, updater and launcher behavior must not be rewritten as part of this patch.

## Verification
TDD must prove:
1. Exact parity at 3.0 s runs the reconstructed worker stage without calling generic Nghia recovery in that tick.
2. Exact parity at >=4.5 s permits generic fallback recovery.
3. Non-parity mode retains the old fallback threshold behavior.
4. Fresh config defaults C2 Adaptive Y OFF.
5. Explicit saved C2 Adaptive Y true/false values are preserved by config load.
6. V10 Strategy source and maps.json hashes are unchanged.
7. Full source tests, compileall, Windows/Nuitka build, launcher smoke and packaged smoke pass before release candidacy.

## Release policy
Build a V10.0.1 Windows candidate first. Do not update public latest.json or publish a stable release until the candidate is verified and explicitly approved for publication.

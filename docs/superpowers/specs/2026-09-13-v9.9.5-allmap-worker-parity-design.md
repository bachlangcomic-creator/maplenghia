# V9.9.5 AllMapWorkerParity Design

## Goal

Move every Spotify farm profile onto a dedicated minimap-driven main farm worker so runtime topology more closely matches the recovered Spotify architecture, while preserving the current recovered per-map behavior and timing.

This release is a topology/ownership change, not a timing retune.

## Baseline

Source baseline: `Nghia_V9.9.4_C2FocusWorkerParity_FullSourceCandidate.zip`.

V9.9.4 already has:

- a dedicated C2 minimap-only farm worker;
- a dedicated Spotify focus cache/worker path;
- `SpotifyMainFarmOrchestrator` with ordered stages `STATE -> SELL_SAFE -> PET -> RECOVERY -> BUFF1 -> BUFF2 -> DISPATCH`;
- single-owner C2 farm dispatch;
- C2 hot-path cached-focus reads rather than direct `_focus_game()` calls;
- supervisor ownership of preview, alert scanning, UI and MiuMiu coordination.

## Scope

Profiles moved to dedicated main-farm ownership:

- C1
- C2
- B1
- B3
- Bunny
- Stand Still
- C1 (Stand Still)
- Red-Nose Pirate Den 2
- Red-Nose Pirate Den 2 (1 Hit)

The existing profile dispatcher remains authoritative:

- SIMPLE profiles -> existing `run_left_and_right` path
- Bunny -> existing `run_bunny`
- Stand Still -> existing `run_stand_still`
- Pirate2 -> existing `run_pirate2`
- Pirate2 1-Hit -> existing `run_pirate2_1hit`

## Non-goals

V9.9.5 must not intentionally change:

- SIMPLE timing constants or humanization probabilities;
- C2 TP -> Skill ordering or C2 micro-timing;
- Bunny route/timing;
- Stand Still anchor/reset/loot timing;
- Pirate2 or Pirate2 1-Hit state-machine timing;
- Buff/Loot/Pet schedules;
- MiuMiu state machine;
- PC Alarm behavior;
- Adaptive Y defaults;
- map coordinates in `maps.json`;
- updater/launcher behavior.

No new per-map worker is introduced. One main farm worker owns all supported Spotify profiles.

## Architecture

### 1. Main farm worker

Replace the C2-specific worker ownership model with a generic Spotify main farm worker.

The worker loop performs only farm-critical work:

1. read the current runtime config;
2. verify the active profile is handled by Spotify parity mode;
3. read the cached game HWND from the focus worker;
4. capture only the minimap ROI;
5. detect the player from the minimap using the existing Spotify detector;
6. apply only profile-specific position observation already required by that profile (for example C2/B3 stability extensions when enabled);
7. honor pause/sell/preview-only gates;
8. call `SpotifyMainFarmOrchestrator.tick(...)` once;
9. yield approximately 1 ms so recovered helper/input sleeps remain the cadence source.

The worker must not perform full-screen template scans, preview rendering, controller FPS pacing, UI work or duplicate farm dispatch.

### 2. Supervisor

The existing full-screen supervisor remains responsible for:

- alert/dead/disconnect/captcha scans;
- full-bag/MiuMiu coordination;
- preview rendering and UI statistics;
- non-farm housekeeping that is already supervisor-owned.

For profiles owned by the main farm worker, the supervisor consumes the latest worker map position when it needs positional context but must not call `SpotifyMainFarmOrchestrator.tick()`.

The supervisor keeps its normal FPS pacing because it is no longer the cadence owner for Spotify farm profiles.

### 3. Focus ownership

Reuse the V9.9.4 `SpotifyFocusCache` path.

The dedicated focus worker remains the only normal-runtime owner of Win32 focus lookup/refresh. Farm-critical code must read:

- `_spotify_cached_game_has_focus()`
- `_spotify_cached_game_hwnd()`

and must not enumerate windows or force foreground focus inside normal parity hot paths.

If cached focus is lost while an action owns input, owned inputs are released immediately and no new key is injected until focus returns.

Legacy direct focus behavior may remain available only when Spotify focus parity is explicitly disabled.

### 4. Input ownership

There is exactly one farm-action owner for an active Spotify profile: the main farm worker.

The supervisor, periodic helper paths and legacy controller must not inject duplicate farm/Pet/skill actions while worker ownership is active.

Sell/MiuMiu handoff remains atomic:

- when a safe-place sell transition begins, farm input is released;
- the sell pause/lock becomes visible before the async seller performs input;
- the farm worker does not resume until the handoff is cleared.

### 5. Profile transitions

Switching maps/profiles must not create overlapping owners.

A worker generation token or equivalent lifecycle guard invalidates the previous profile loop immediately. State reset continues to use the existing behavior-engine/core reset mechanisms.

The worker may remain one long-lived thread that consumes current runtime config; if implementation reuses the current generation model, only one live generation may own farm input.

### 6. Position handling

Use one generic minimap capture path where possible.

Do not change existing Spotify map coordinates or SIMPLE edge logic.

Profile-specific extensions remain explicit and opt-in:

- C2 outlier/Adaptive-Y behavior remains unchanged;
- B3 Adaptive Y remains unchanged and off by default if that is the V9.9.4 default;
- other profiles must not silently gain Adaptive Y or C2-specific outlier semantics.

## Timing invariants

V9.9.5 must lock rather than retune recovered timings.

At minimum, tests must protect the currently reconstructed values used by the existing routines, including:

- SIMPLE pre-combo sleep `0.05 s`;
- SIMPLE outer hold `200..500 ms`;
- SIMPLE fall confirmation around `2.5 s`;
- SIMPLE fall recovery action `200..600 ms`;
- SIMPLE human-rest branch around 2% with `3..5 s` rest;
- SIMPLE human/jump branch through about 8% with `150..300 ms` action;
- C2 action hold `20..50 ms`;
- C2 pair wait `0.05..0.15 s`;
- C2 outer window `0.2..0.5 s`;
- C2 pre-combo `0.05 s`;
- PyDirectInput pause `0.1 s`;
- existing Bunny, Stand Still, Pirate2 and Pirate2 1-Hit timing/state constants exactly as present in the V9.9.4 baseline.

The implementation must not reduce these values merely to make farm behavior look faster.

## Failure handling

On capture failure, focus loss, STOP, profile invalidation, sell lock, pause reason, preview-only mode or worker exception:

- release all owned movement/action inputs;
- do not inject a new farm key while blocked;
- allow the supervisor/alert/MiuMiu paths to continue independently where appropriate;
- recover without creating a second farm owner.

A repeated minimap capture failure may be logged with throttling, but logging must not become a hot-path delay.

## Tests

TDD coverage is required before implementation changes.

### Ownership tests

- each supported profile is worker-owned in Spotify runtime parity mode;
- supervisor skips farm dispatch for every worker-owned profile;
- exactly one `SpotifyMainFarmOrchestrator.tick()` owner exists per active profile;
- periodic helper paths do not duplicate Pet/farm actions.

### Focus tests

- SIMPLE/Bunny/Stand/Pirate hot paths consume cached focus state;
- direct `_focus_game()`/`_game_has_focus()` lookup is not required on the parity hot path;
- cached focus loss blocks input before new ownership;
- mid-action cached focus loss releases owned keys.

### Dispatch tests

- C1/B1/B3 still dispatch to SIMPLE/left-right behavior;
- Bunny/Stand/Pirate2/Pirate2 1-Hit dispatch to their existing dedicated routines;
- C2 continues to use its existing TP+Skill parity helper;
- map/profile switches do not leave two active owners.

### Timing regression tests

- hash/content guards or explicit constant assertions protect all recovered timing/state constants touched by the change;
- C2 V9.9.4 timing tests remain green unchanged;
- non-C2 timing/state-machine tests are added before refactoring worker ownership.

### Integration tests

- MiuMiu safe-place handoff remains atomic;
- Recovery/Buff/Loot/Pet ordering remains `STATE -> SELL_SAFE -> PET -> RECOVERY -> BUFF1 -> BUFF2 -> DISPATCH`;
- preview/alert supervisor remains live while farm cadence is worker-owned;
- STOP and focus-loss paths deterministically release input.

## Acceptance criteria

V9.9.5 is acceptable when:

1. all supported Spotify profiles are farmed by one dedicated minimap-only main farm worker;
2. the full-screen supervisor never owns farm cadence for those profiles;
3. focus lookup/refresh is worker/cache-owned and farm hot paths only consume cached focus in parity mode;
4. no recovered per-map timing/route is intentionally changed;
5. no duplicate farm/Pet input path exists;
6. C2 V9.9.4 tests continue to pass;
7. new all-map ownership/focus/dispatch/timing tests pass;
8. compileall passes;
9. protected unrelated modules (MiuMiu, PC Alarm, updater/launcher) remain unchanged unless a test proves a required interface-only edit;
10. Windows/Nuitka build and launcher smoke are run before any stable publish.

## Release boundary

Implement and validate V9.9.5 as a candidate first. Do not update stable `latest.json` or publish a stable release until Windows build, smoke and release verification pass. Publishing remains release-asset-first and manifest-last.

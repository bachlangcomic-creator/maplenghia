# Nghia V9.9.0 Disconnect Watchdog Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ONL/disconnect detection use the recovered Spotify `ONL_B64` threshold `0.95` and route one debounced disconnect reaction through the existing watchdog without reconnect/session behavior.

**Architecture:** Build V9.9.0 as an overlay on the verified public V9.8.1 Portable. Replace `spotify_detection_parity.py` with a V9.9 copy derived from V9.8.0, and patch only the host scan/emit bridge needed to use `DISCONNECT_THRESHOLD=0.95` and debounce reactions. Asset identity and threshold are Direct; because the exact frame/crop caller path is only High-structural, the final detector result remains `spotify_structural` rather than being mislabeled `spotify_exact`.

**Tech Stack:** Python 3.12, pytest, OpenCV-compatible frame matching, existing `spotify_exact_assets.py`, `SpotifyWatchdogWorker`, and `MapleNghiaPro` host bridge.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.9.0-forensic-parity-design.md`

- CAPTCHA remains detect/pause/alert only; no solver or generative-AI path.

- [ ] **Step 5: Add one-shot reaction helper**

```python
def _spotify_disconnect_reaction(self, result, cfg):
    if not result.matched:
        self.spotify_disconnect_latched = False
        return False
    if self.spotify_disconnect_latched:
        return False
    self.spotify_disconnect_latched = True
    self._spotify_watchdog_request_pause("disconnect", cfg)
    if cfg.get("alert_dc"):
        self._handle_alert("dc", "Phát hiện mất kết nối / hộp thoại kết nối.", cfg)
    return True
```

Route `result.kind in ("dc", "disconnect")` in `_spotify_watchdog_emit` to this helper. Existing `_handle_alert` remains responsible for its configured Telegram path; do not create a second Telegram sender.

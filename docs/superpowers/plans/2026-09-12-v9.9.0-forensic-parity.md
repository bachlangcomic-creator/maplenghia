# Nghia V9.9.0 Forensic Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver V9.9.0 as five independently verified Spotify-forensic parity improvements assembled into one private-preflight release candidate.

**Architecture:** The approved design spans five independent subsystems, so implementation is intentionally split into five focused TDD plans plus one integration/release plan. All plans produce files under the same `release_payload/v9.9.0/` overlay; cumulative host/core patch files are rebased after each subsystem so the final overlay applies once to the exact public V9.8.1 base.

**Tech Stack:** Python 3.12, pytest, GitHub Actions Windows, PowerShell, existing Nghia overlay/patch release pipeline.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.9.0-forensic-parity-design.md`

## Global Constraints

- Branch: `release-v9.9.0-forensic-parity`.
- Base: exact public V9.8.1 Portable SHA-256 `e36350ab7e8285f3e7f0c4d1cc80aee9c88d4c5927249bb11dcc40b989694d46`.
- Evidence labels remain `direct`, `high_structural`, or `nghia_fallback`; High-structural behavior is never relabeled Direct.
- No `session_monitor_worker`, `check_session`, login/license/session enforcement, KICK-driven disabling, CAPTCHA solver, Gemini/generative AI, or automated CAPTCHA answering.
- V9.8.1 C1/C2/B1/B3 shared hold-combo semantics remain protected.
- Dynamic Combo remains dormant/evidence-gated; Pirate Laptop remains out of scope.
- Public publishing is forbidden until a successful private preflight is reported and the user explicitly says `publish V9.9.0`.

# Nghĩa V9.8.0 All Cure, Dynamic Combo & Main Farm Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover the remaining non-session Spotify subsystems requested for V9.8—Auto Market All Cure, dynamic combo caller wiring, and evidence-backed `main_farm_worker` topology—without speculative coordinates, timing, or scheduler rewrites.

**Architecture:** Auto Market All Cure is isolated in its own worker with serialized input ownership and fail-closed action steps. Dynamic combo and main-farm changes are forensic-first: code is wired only after an explicit recovered caller/order fixture exists; otherwise current V9.7 behavior remains untouched and tests lock that non-wiring.

**Tech Stack:** Python 3.12, threading, pytest, static AST/source inspection, raw Nuitka payload for forensic evidence, existing Nghĩa input bridges.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.8.0-exact-detector-watchdog-recovery-design.md`

## Global Constraints

- Requires Plans 1 and 2 to be complete first.
- Auto Market All Cure is opt-in and must not overlap C2, MiuMiu, revive, or normal farm input ownership.
- No NPC/shop/market coordinates, sleeps, prices, retry counts, or click order may be invented.
- Dynamic combo may be wired only when a real caller/config/map branch is recovered.
- C2 must never be routed through generic dynamic combo.
- `main_farm_worker` recovery is incremental; no wholesale thread/scheduler rewrite from symbol names alone.
- No session-monitor/login/license/session behavior.

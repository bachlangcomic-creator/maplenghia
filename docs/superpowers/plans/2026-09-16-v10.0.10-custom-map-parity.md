# V10.0.10 Custom Map Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build V10.0.10 from V10.0.9 and add optional Custom Map SIMPLE-parity behaviors without changing existing maps or default custom-map behavior.

**Architecture:** V10.0.9 is the immutable release base. Extend `nghia_strategy_v10.py` with isolated feature flags for human idle/jump behavior, fall recovery, loot jitter, and custom-map Adaptive Y. Expose the flags only in the Custom Map builder/config UI, defaulting OFF, persist them in the generated V10 profile/runtime config, and keep Top Loot B3 separate. Publish only after source regression, Windows/Nuitka build, PE verification, launcher smoke, packaged smoke, release asset verification, and stable `latest.json` promotion succeed.

**Tech Stack:** Python 3.12, tkinter/customtkinter, pytest, GitHub Actions, Nuitka, PowerShell.

**Spec:** Conversation-approved V10.0.10 design: V10.0.9 base + optional Custom Map SIMPLE Human Behavior, B1/B3-style fall recovery, Spotify-style loot jitter, and Custom Map Adaptive Y; all new options OFF by default; Top Loot B3 excluded.

## Global Constraints

- Base artifact must be V10.0.9, not V10.0.8.
- Preserve V10.0.9 MiuMiu timer UI and CAPTCHA 1280x720 client-area capture.
- Preserve Adaptive Y C2/B3, Anti-Jitter, STOP Non-Blocking, Loot Parity Defense, combat/TP/skill cadence, and bundled `maps.json` unless a test explicitly covers intended Custom Map behavior.
- New Custom Map flags default OFF and OFF must retain V10.0.9 Custom Map behavior.
- Top Loot B3 remains separate and is not added to this feature set.
- Stable `latest.json` must not move to 10.0.10 until all build/release verification passes.

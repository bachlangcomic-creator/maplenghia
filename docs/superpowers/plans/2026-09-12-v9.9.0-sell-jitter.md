# Nghia V9.9.0 Auto-Sell Jitter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace V9.8.1 fixed sell scheduling with the recovered High-structural Spotify jitter formula while keeping the watchdog as the sole timer owner and exposing only one pending sell-due request to the farm loop.

**Architecture:** Replace the V9.8 watchdog module with a V9.9 copy that imports `random`, computes one randomized delay, and latches a pending due state instead of repeatedly firing/rescheduling. The existing host `spotify_sell_timer_event` remains the cross-subsystem request signal; only `notify_sell_completed()` starts a fresh randomized period after successful selling.

**Tech Stack:** Python 3.12, `random.uniform`, `time.monotonic`, `threading.Event`, pytest.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.9.0-forensic-parity-design.md`

## Global Constraints

- Base artifact: public `NghiaClient_V9.8.1_Portable.zip`, SHA-256 `e36350ab7e8285f3e7f0c4d1cc80aee9c88d4c5927249bb11dcc40b989694d46`.
- Literal evidence `10`, `10`, `max`, `1.2`, `random.uniform`, `60` is Direct.
- Formula `uniform(max(10,m-10), m*1.2) * 60` is **High-structural**, never Direct.
- Watchdog is the only sell timer owner; the main-farm orchestrator must not compute a second delay.
- Timer maturity creates one pending request; it does not call MiuMiu directly.
- Successful sell resets `last_sell_time`, clears pending state, and creates the next randomized delay.
- Disabling auto-sell clears stale delay and pending state.
- Do not change MiuMiu image matching, safe-place verification, cooldown, or full-bag condition semantics.

- [ ] **Step 4: Create V9.9 watchdog copy and implement only the recovered formula**

```python
import random


def get_next_sell_delay(self, cfg):
    minutes = max(0.0, float(cfg.get("sell_interval_minutes", 30.0)))
    low_minutes = max(10.0, minutes - 10.0)
    high_minutes = minutes * 1.2
    if high_minutes < low_minutes:
        high_minutes = low_minutes
    return random.uniform(low_minutes, high_minutes) * 60.0, "spotify_structural"
```

The `high < low` clamp is a Nghia safety fallback for malformed/sub-10-minute config and must be documented in evidence/tests as `nghia_fallback`; it is not Spotify evidence.

import spotify_watchdog as wmod


class Host:

def test_due_latches_once_until_sell_completed(monkeypatch):

Scheduling:

```python
def _sell_schedule_step(self, cfg):
    if not cfg.get("auto_sell_timer_enabled"):
        self.next_sell_delay = None
        self.sell_due_pending = False
        self.last_sell_time = time.monotonic()
        return
    if self.sell_due_pending:
        return
    if self.next_sell_delay is None:
        self.next_sell_delay, _source = self.get_next_sell_delay(cfg)
    now = time.monotonic()
    if now - self.last_sell_time < self.next_sell_delay:
        return
    self.sell_due_pending = True
    self.host._spotify_watchdog_sell_timer_due(cfg)
```

Completion:

```python
def notify_sell_completed(self, now=None):
    self.last_sell_time = time.monotonic() if now is None else float(now)
    self.next_sell_delay = None
    self.sell_due_pending = False
```

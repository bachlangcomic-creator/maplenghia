# Nghia V9.9.0 All Cure External Asset Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make All Cure remain fail-closed today while becoming automatically asset-ready when all 12 original external PNGs are later placed in `user_data/all_cure_images/`, without modifying the core again.

**Architecture:** Add a stdlib-only asset gateway that validates exact filenames and PNG structure independently of market clicks. The existing `SpotifyAllCureMarketWorker` gains three explicit gates: config enabled, asset gateway READY, workflow evidence READY. `MapleNghiaPro` supplies the persistent user-data directory and continues to own serialized side effects; any blocked gate produces zero market actions.

**Tech Stack:** Python 3.12 stdlib (`pathlib`, `struct`, `zlib`, `binascii`), pytest, existing All Cure worker/host bridge, launcher updater transaction tests.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.9.0-forensic-parity-design.md`

## Global Constraints

- Asset directory is exactly `user_data/all_cure_images/`, outside `app_payload`.
- Required filenames are exactly: `empty.png`, `npc_all_cure.png`, `all_cure_line.png`, `confirm_all_cure.png`, `buy_all_cure.png`, `finish_buying.png`, `shop.png`, `exit.png`, `all_cure_pots.png`, `set_sell_item.png`, `confirm_set_item_to_sell.png`, `complete_set_item.png`.
- Missing one required name, corrupt PNG, invalid CRC/zlib payload, wrong signature, or disabled config keeps the transaction BLOCKED.
- BLOCKED must perform zero `_spotify_market_run_action` calls.
- Do not synthesize images, rename approximate images, use OCR, or fall back to coordinate-only market clicking.
- Updater must not overwrite/delete `user_data/all_cure_images/`.
- Original 12 PNGs are absent from the supplied Spotify package; V9.9 must not claim pixel-identical assets until originals are supplied and independently verified.
- Existing recovered quantity `100`, coordinates `(115,543)` and `(766,397)`, buy-to-sell delay `1.0s`, and failure retry `2.0s` stay evidence-only and are not changed by gateway validation.

```python
import binascii, struct, zlib


def chunk(kind, data):
    body=kind+data
    return struct.pack('>I',len(data))+body+struct.pack('>I',binascii.crc32(body)&0xffffffff)


def tiny_png():
    sig=b'\x89PNG\r\n\x1a\n'
    ihdr=struct.pack('>IIBBBBB',1,1,8,0,0,0,0)
    raw=b'\x00\x00'
    return sig+chunk(b'IHDR',ihdr)+chunk(b'IDAT',zlib.compress(raw))+chunk(b'IEND',b'')
```

- [ ] **Step 4: Implement strict stdlib PNG validation**

Required validator behavior:

```python
PNG_SIG=b'\x89PNG\r\n\x1a\n'


def _valid_png(raw: bytes) -> bool:
    if not raw.startswith(PNG_SIG): return False
    pos=8; saw_ihdr=False; saw_idat=False; saw_iend=False; idat=[]
    while pos + 12 <= len(raw):
        size=struct.unpack('>I',raw[pos:pos+4])[0]; pos += 4
        kind=raw[pos:pos+4]; pos += 4
        if pos + size + 4 > len(raw): return False
        data=raw[pos:pos+size]; pos += size
        want=struct.unpack('>I',raw[pos:pos+4])[0]; pos += 4
        if (binascii.crc32(kind+data)&0xffffffff) != want: return False
        if kind == b'IHDR': saw_ihdr = len(data) == 13
        elif kind == b'IDAT': saw_idat=True; idat.append(data)
        elif kind == b'IEND': saw_iend = size == 0; break
    if not (saw_ihdr and saw_idat and saw_iend): return False
    try: zlib.decompress(b''.join(idat))
    except zlib.error: return False
    return True
```

`validate()` checks only exact required filenames and returns sorted tuples in required-file order for stable diagnostics.

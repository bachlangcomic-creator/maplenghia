# Nghia V9.9.0 Pirate Micro-Timing Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the newly recovered Pirate Den normal and Pirate Den 1 Hit state/timing evidence without changing V9.8.1 shared hold-combo semantics or turning 1-Hit FARM into spam.

**Architecture:** Patch only `spotify_recovered_core.py` on top of public V9.8.1. New constants are evidence-named and centralized; existing FARM/sweep/top-loot state machines remain intact. Tests drive the real Pirate step functions with fake time/random values and static guards protect one-hit semantics, Dynamic Combo dormancy, and C1/C2/B1/B3.

**Tech Stack:** Python 3.12, pytest, existing `SpotifyRecoveredCore` state machine and fake-host fixtures.

**Spec:** `docs/superpowers/specs/2026-09-12-v9.9.0-forensic-parity-design.md`

## Global Constraints

- Preserve V9.8.1 `_spotify_hold_combo_action(cfg, direction_key, flash_key, skill_key, hold_time)` unchanged.
- Pirate normal FARM shared combo remains random `0.200..0.500s`.
- Pirate normal sweep remains `1.6s`; Pirate 1 Hit sweep remains `1.5s`.
- Pirate 1 Hit FARM never calls `_spotify_hold_combo_action`.
- Dynamic Combo remains dormant/evidence-gated; Pirate Laptop remains out of scope.
- Only values listed in `evidence/pirate_microtiming.json` may be added/changed.
- Any input exception through a new recovery/edge path must call `_release_all_owned_inputs()` before propagating/returning.
- C1/C2/B1/B3 SIMPLE route, bounds, focus/HWND, Adaptive Y, and recovered hold-combo cadence are protected.
